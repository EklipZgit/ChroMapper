## Input System tests

Input tests must not depend on editor focus, Xvfb, physical hardware, or devices discovered by the host operating system. Reference `Unity.InputSystem.TestFramework`, activate an `InputTestFixture`, and add dedicated virtual `Mouse` and `Keyboard` devices for the test when emulating input in a test.

Do not use `Mouse.current` or `Keyboard.current` before creating the fixture-owned devices. When a test already inherits a project fixture such as `TestBase`, compose `InputTestFixture` and call `Setup()` and `TearDown()` explicitly. Dispose action assets created in the isolated runtime before teardown; restore shared application action maps only after teardown restores the original Input System.

`InputSystem.Update()` may be called manually while `InputTestFixture` owns the runtime when the behavior under test requires multiple reports in one rendered frame. Outside that fixture, let Unity's player loop process input. Assertions should prove that the intended production callback ran rather than relying on pre-existing static state.

The authored action and composite conventions are documented in [the input architecture guide](../Input/README.md).

## Jenkins audio limitation

Jenkins runs Linux Unity in batchmode under Xvfb. That environment does not provide a dependable native audio playback clock: `AudioSource.Play()` may not make `AudioSource.isPlaying` true, and `AudioSource.time` or `timeSamples` may not advance. Windows batchmode can provide working audio, so a passing local CLI run alone does not prove that an audio-dependent test is Jenkins-safe.

Tests of playback-driven behavior must use a deterministic test clock and retain the production behavior they claim to cover, including playback state, `OnPlayToggled`, `OnTimeChanged`, and callback-controller frame ordering. Explicitly stop native audio in the test so Windows exercises the same unavailable-backend condition. Do not replace the production callback path with a direct visual refresh merely to avoid the audio dependency.

`BasicEventChunkingTestBase.StartDeterministicPlaybackAtSongBpmTime` and `PauseDeterministicPlayback` are the established helpers for Basic Event chunking tests.

## Map reload ownership

The mapper scene survives an in-place test-map reload, but the environment scene does not. Clear generated geometry through its owning collection before unloading the environment so the collection cannot retain destroyed scene objects. Destroying the geometry must also detach its animation-track children. `MapReloadLifetimeTest` checks both registrations and destruction of the outgoing Unity objects.

`TestUtils` owns the synthetic audio clip it creates. Replacing that clip stops playback, rebinds the audio source, and explicitly destroys the superseded native clip. Keep only the current clip, rather than accumulating clips across fixture reloads or destroying audio assets the helper does not own. The lifetime regression repeats reloads and checks that the old clips are destroyed and the source uses the current clip.

The CLI runner prints failure messages and stacks. Complete captured test diagnostics remain in the timestamped XML and Unity log under `TestResults/cli`, including debug output from successful tests.

`AuroraMapParityTest` compares the complete Aurora difficulty with reduced laser, cloud, cave, and cliff fixtures. The laser oracle uses the shipped Billie scene's pre-Start quaternions and Chroma's locked rotation events, including direction changes. It checks the cached rest pose, applied rotation, and projected V angle at 6.375, 11.75, 16.5, 24, and 60.5, followed by a reverse seek. `AuroraLaserFixture.json` isolates the resting pose with two pillar enhancements, two light events, and the opening player position. `AuroraLaserMotionFixture.json` also preserves the rotation events through beat 65.

Obstacle assertions compare core/frame dimensions, pivots, and leading world Z with Noodle's lane-unit size and the shipped StretchableObstacle values. Pixel tests require the tiny cave and cliff faces to retain gray/white RGB at zero bloom alpha after animated scaling. Additional cases cover V2/V3 positive, zero, and negative lengths and nonzero laser start angles. Cloud/glow compositing coverage remains in the same fixture. Late cliff captures use a teardown-owned deterministic playback clock and a render-stage probe after LateUpdate, covering beats 478, 580, and 600 while asserting definite position replaces travel. Captures retain the fixture name under `TestResults/AuroraMapParityTest`. Render resources are released in `finally`, including on assertion failure. `TestUtils.ReloadMap` accepts optional difficulty metadata so NJS and characteristic are installed before providers initialize.

`CensoredLaserResetParityTest` loads the complete CENSORED!! ExpertPlus difficulty and a two-pair reduction. The reduction preserves the last locked speed event, the unlocked beat-164 reset, track parenting, and the parent's collapse/restoration. The test crosses beat 159.96 while that parent is collapsed, so the future reset snapshot must sample its callback-time world Z instead of the rendered Z=0. An independent native/Chroma oracle checks both sides of all eight FitBeat pairs at 147.906, 163.9, and 164.031, including rewind. Five cases cover paused seeks, deterministic playback without native audio, and a parent with translation, rotation, and scale. Preserve the oracle JSON before loading because production loading consumes mutable custom-event data. Full-map renders live under `TestResults/CensoredLaserResetParityTest`; render resources are released in `finally`, preview/clock/settings state is restored in Unity teardown, and class teardown reloads an empty map.

`CensoredLaserColorParityTest` checks the full difficulty and a two-event reduction at 164.031. The shipped FitBeat ColorSO supplies normal alpha .7490196 to Chroma's custom RGB `(0.556, 0.641, 1)`, before the tube's serialized alpha multiplier. Existing tube lights must use those absolute endpoints with native parametric shaders. A controlled full-map render compares native alpha with the old normalized alpha while keeping bloom, camera, RGB, and geometry fixed. It requires retained white near cores and more blue in the affected far-body/fringe pixels. The third case checks flash/fade clocks, custom alpha and brightness, boosted endpoints, white, off, and reverse seeks through real scene tubes. Captures under `TestResults/CensoredLaserColorParityTest` identify the actual and normalized inputs. Readback/render textures are destroyed in `finally`, changed controller colors are restored there, and preview/camera/animation/bloom settings are restored in Unity teardown.

`BasicLightAdapterAlphaParityTest` registers 13 concrete adapters with the real Billie basic-light effect. It reads material property blocks, directional intensity, sprite/particle alpha, gradient tint, combined/lightmap/color-array inputs, and renderer visibility across normal, flash, fade, white, off, boost, and reverse seeks. Native ColorSO factors apply before each adapter's own multiplier. An additional case checks that instanced color-only materials retain their first dispatched alpha. Every probe is unregistered and its GameObject destroyed in teardown, including on failure. Basic gradient, HSV, and edit/undo preview assertions use native scene alpha while ribbons continue to display authored alpha. GLS and fire-curve alpha keep their separate native behavior.
